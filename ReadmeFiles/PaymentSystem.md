## 📖 نظرة عامة

**Paylio** منصة دفع إلكتروني تتيح للمستخدمين إنشاء حساب مالي، وتوثيق هويتهم (KYC)، وتحويل الأموال فيما بينهم، وطلب المدفوعات وتسويتها، وإدارة بطاقاتهم الائتمانية، ومتابعة كل معاملة وإشعار من لوحة تحكم واحدة. وفي المقابل، تحصل الإدارة على لوحة تحكم احترافية للتحكم الكامل في الحسابات والمعاملات ومحتوى الموقع.

يعمل المشروع بواجهتين متكاملتين: **واجهة ويب** جاهزة للمستخدم النهائي، و**REST API** تغطي كل العمليات الأساسية لربط تطبيقات الموبايل أو أي عميل خارجي.

## ✨ المميزات الرئيسية

### 👤 الحسابات والهوية
- **إنشاء حساب مالي تلقائي** لكل مستخدم جديد عند التسجيل، مع توليد رقم حساب فريد ومعرّف حساب ورقم PIN من 4 أرقام.
- **التسجيل وتسجيل الدخول بالبريد الإلكتروني** عبر نموذج مستخدم مخصص (`Custom User Model`).
- **توثيق الهوية (KYC)**: الاسم الكامل، صورة شخصية، نوع الهوية (بطاقة وطنية / رخصة قيادة / جواز سفر)، صورة الهوية، التوقيع، العنوان، وبيانات التواصل.
- **حالة الحساب ومراجعة KYC** (`active` / `pending` / `in-active`) يديرها المشرف من لوحة الإدارة.
- **حذف الحساب** بخطوة تأكيد مستقلة.

### 💸 التحويلات المالية
- **البحث عن المستلم** برقم الحساب أو معرّف الحساب.
- **مسار تحويل من عدة خطوات**: إدخال المبلغ ← شاشة تأكيد ← التحقق من **رقم PIN** ← صفحة إتمام العملية.
- **التحقق من كفاية الرصيد** قبل إنشاء المعاملة.
- **إشعارات فورية** للطرفين: تنبيه إيداع للمستلم وتنبيه خصم للمرسل.

### 📨 طلبات الدفع (Payment Requests)
- إرسال طلب دفع إلى أي مستخدم عبر رقم حسابه.
- يصل الطرف الآخر إشعار بالطلب، ويمكنه **تسويته** بعد شاشة تأكيد وتحقق من PIN، أو **حذفه**.
- تتبّع دورة حياة الطلب بحالات واضحة: `request_sent` ← `request_processing` ← `request_settled`.

### 💳 إدارة البطاقات الائتمانية
- عرض تفاصيل البطاقة (Visa / Mastercard / Verve).
- **شحن البطاقة** من رصيد الحساب، و**سحب الأموال** منها إلى الحساب.
- **حذف البطاقة**، مع إشعار لكل عملية.

### 📊 المعاملات والإشعارات ولوحة التحكم
- **لوحة تحكم للمستخدم** تعرض الرصيد والبطاقات وآخر العمليات.
- **سجل المعاملات** الكامل مع صفحة تفاصيل لكل معاملة، ومعرّف فريد لكل واحدة (`TRN...`).
- أنواع معاملات متعددة: تحويل، استلام، سحب، استرجاع، طلب دفع.
- **نظام إشعارات** بعدّاد للإشعارات غير المقروءة، مع اسم المرسل وصورته.

### 🌍 دعم اللغتين العربية والإنجليزية
- واجهة **ثنائية اللغة** مع اللغة العربية كلغة افتراضية.
- تبديل اللغة من الواجهة مباشرة عبر `i18n`.
- إدارة الترجمات من المتصفح بواسطة **Django Rosetta** دون تعديل ملفات الترجمة يدويًا.

### 🛠️ لوحة إدارة احترافية
- واجهة إدارة بتصميم داكن عبر **Django Jazzmin**.
- تعديل الرصيد وحالة الحساب وحالة KYC مباشرةً من قائمة الحسابات.
- **استيراد وتصدير** بيانات الحسابات وبيانات KYC (`django-import-export`).
- **إدارة محتوى الموقع من لوحة الإدارة**: الشعار، الأيقونات، إحصائيات الصفحة الرئيسية، الأسئلة الشائعة، صفحة "من نحن"، بيانات التواصل، وروابط التطبيقات.

### 🔌 REST API متكاملة
- تغطي: المصادقة، الحساب، KYC، لوحة التحكم، البطاقات، التحويلات، طلبات الدفع، والمعاملات.
- **مصادقة بالتوكن** (`Token Authentication`) مع تسجيل وخروج عبر API.
- صفحة **API Dashboard** داخل المشروع تعرض نقاط النهاية مصنّفة حسب الوظيفة.

## 🚀 التشغيل محليًا

### المتطلبات
- Python 3.11 أو أحدث
- pip
- Git

### الخطوات

```bash
# 1) استنساخ المشروع
git clone https://github.com/Islam412/Payment-system.git
cd Payment-system

# 2) إنشاء بيئة افتراضية وتفعيلها
python -m venv venv
source venv/bin/activate        # Linux / macOS
venv\Scripts\activate           # Windows

# 3) تثبيت المكتبات
pip install -r requirements.txt

# 4) تجهيز قاعدة البيانات
python manage.py migrate

# 5) إنشاء حساب مشرف
python manage.py createsuperuser

# 6) تشغيل الخادم
python manage.py runserver
```

افتح المتصفح على `http://127.0.0.1:8000/` وسجّل الدخول إلى لوحة الإدارة من `http://127.0.0.1:8000/admin/`.

> **ملاحظة:** بعد الدخول إلى لوحة الإدارة، أضف سجلًا واحدًا على الأقل في **Company** و**Home** لتظهر بيانات الموقع في الصفحات العامة.

### متغيرات البيئة

| المتغير | الوصف | الافتراضي |
|---|---|---|
| `DATABASE_URL` | رابط قاعدة البيانات (مثل PostgreSQL) | SQLite محلية |
| `ALLOWED_HOSTS` | النطاقات المسموحة، مفصولة بفواصل | `*` |

## 🔌 أهم نقاط الـ API

| المجموعة | المسار | الوظيفة |
|---|---|---|
| المصادقة | `POST /user/api/register/` · `POST /user/api/login/` · `POST /user/api/logout/` | التسجيل والدخول والخروج |
| الحساب | `GET /account/api/account/` · `GET /account/api/dashboard/` | بيانات الحساب ولوحة التحكم |
| KYC | `GET/POST /account/api/kyc/` | عرض بيانات التوثيق وإرسالها |
| التحويلات | `/api/amount-transfer/…` · `/api/transfer-confirmation/…` · `/api/transfer-final/…` | مسار التحويل الكامل |
| طلبات الدفع | `/api/amount-request/…` · `/api/settlement-process/…` | إرسال الطلبات وتسويتها |
| البطاقات | `/api/credit-cards/<card_id>/` · `fund/` · `withdraw/` · `delete/` | إدارة البطاقات |
| المعاملات | `GET /api/transactions/` · `GET /api/transactions/<id>/` | سجل المعاملات وتفاصيلها |

تجد القائمة الكاملة في صفحة **API Dashboard** داخل التطبيق.

**مثال — تسجيل الدخول:**

```bash
curl -X POST http://127.0.0.1:8000/user/api/login/ \
  -H "Content-Type: application/json" \
  -d '{"email": "user@example.com", "password": "StrongPass123"}'
```

ثم استخدم التوكن الراجع في باقي الطلبات:

```bash
curl http://127.0.0.1:8000/account/api/account/ \
  -H "Authorization: Token <your-token>"
```

## ☁️ النشر

المشروع جاهز للنشر على **Railway**:

- `Procfile` يشغّل التطبيق عبر **Gunicorn** مع عمّال **gevent** للتعامل مع الطلبات المتزامنة.
- **WhiteNoise** يقدّم الملفات الثابتة دون خادم إضافي.
- **Cloudinary** يخزّن الوسائط المرفوعة خارج نظام ملفات الخادم.
- `DATABASE_URL` يوجّه التطبيق تلقائيًا إلى **PostgreSQL** في بيئة الإنتاج.
